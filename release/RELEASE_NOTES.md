# 0.1.3 · 来源验证修复与首次接入

国内第一方入口已上线 `0.1.3`，真实 HTTPS、一次来源接入及 `0.1.2 → 0.1.3` 启动自动升级均已通过验收。

- 修复来源迁移时的误报：原生宿主已返回真实安装项时，优先核验该项来源；插件不必同时出现在 `available` 列表。保留配置与有效来源不符时的拒绝检查。
- 补全首次接入：先检查连接，再由本人登录，最后以当前身份和获权目录核验能力。Codex 设置入口与主业务 Skill 使用同一流程。
- 只读诊断区分网络认证、TLS/DNS/超时、服务和 OAuth 元数据异常以及宿主加载状态，不将 `not_logged_in` 当作唯一原因，也不要求员工换热点。
- 员工通过国内第一方入口安装和更新，不依赖 GitHub 或 VPN；GitHub 保留为维护者通道。本地 ZIP 仅支持手动导入，持续更新需要登记 Git 来源。
- 已核对宿主启动时后台检查 Git revision 并更新缓存的行为，不承诺固定轮询或聊天热加载；离线时保留原安装。
- 保持原 MCP 服务名、地址及本人业务确认规则，升级不主动删除 OAuth 或增加业务权限。
- WorkBuddy 同步共享说明和脚本；完整客户端导入与 OAuth 尚待验收。

17 个分发文件、三个 ZIP 的 SHA256 和内容校验通过，公司隔离 CI 的 96 项测试、共享源同步及构建检查通过。实际国内入口的 43 个公共文件、状态/MIME/哈希、404/POST 拒绝、TLS Git 提交与内容核验通过。

保留的 `0.1.2` 隔离安装仅启动 app-server 即更新到 `0.1.3`，没有手动升级或改写来源；另一个本地 `0.1.2` 安装仅执行一次接入，首次直接返回 `ready`，实际版本和 Git/main 来源匹配。真实宿主已核验 OAuth 保留和只读能力，Windows 自动换行差异单独记录，未冒充原始字节一致。完整范围见[交接](../docs/handoff/2026-10-26_onboarding-candidate.md)。

`0.1.2` 国内发行对象与下载保持原字节，历史公开 `0.1.1` Release 不覆盖。本仓只接收规范源经验证的制品。
