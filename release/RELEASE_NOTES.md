# 0.1.2 · 首次接入与连接恢复

本机验收候选，尚未公开发行；国内员工分发与更新入口尚未部署。

补全员工首次接入流程：先检查连接，再完成本人登录，最后以当前身份和获权目录验证可用能力。

- Codex 包声明标准设置引导；主业务 Skill 在首次使用、询问能力或工具缺失时进入同一流程。
- 随包只读诊断区分网络认证、TLS/DNS/连接错误、服务与 OAuth 元数据异常、需要授权及宿主工具加载状态。`not_logged_in` 不再被当作网络失败的唯一解释。
- 网络可用且用户已要求登录时，推进宿主原生授权；企业身份、范围和业务确认继续由本人在第一方页面完成。
- 员工安装和更新以国内灼见官方入口为交付目标，不依赖员工访问 GitHub 或配置 VPN；最终制品已完成本机静态分发验收，正式入口尚未部署，GitHub 只保留为维护者通道。
- 已核对的 Codex 版本在宿主启动时后台检查 Git 更新源，新 revision 可刷新已安装插件缓存。首次安装、原生升级、启动自动升级和离线保留安装已在隔离 fixture 中通过；这不是固定周期轮询，也不等于当前聊天热加载或国内现网已启用。旧 `0.1.1` 的本地或境外来源需要一次迁移；本地 ZIP 路径不具备自动联网更新能力。
- 保持原 MCP 服务名与地址，不因升级删除现有授权，不新增业务权限；现有聊天需要时刷新或新开聊天核验。
- WorkBuddy 共享说明和诊断资源，未宣称其安装引导机制或完整客户端 OAuth 已实测。

本仓库仅接收规范源经验证的构建产物。发布与实际验收范围以交接记录和本版本 SHA256 回执为准，不覆盖历史 `0.1.1` 安装包。安装、更新与网络异常处理见仓库首页 README。

本候选的 17 个交付文件和三个 ZIP 已通过哈希及归档内容验证；最终真实包通过本机 Nginx `1.28.0` 六项检查与 Git clone。状态与未测边界见[本次交接](../docs/handoff/2026-10-26_onboarding-candidate.md)。

本机最终安装文件已与构建核对一致，Codex 只读业务联通通过。当前安装仍使用本地来源，`automaticUpdateSourceLive=false`；没有据此宣称国内员工自动更新已经启用。
