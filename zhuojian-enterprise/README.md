# 灼见企业 · Codex 连接包

源码目录是连接模板，其中 `.invalid` 地址不能使用；维护者通过构建脚本明确传入 MCP 地址，生成独立连接包。包版本以根清单 `plugin.json` 为准，已发行版本以核验过的第一方发行记录及字节摘要为准。源码、构建完成和宿主已安装，均不能代替服务部署与实际授权验收。

包采用根目录 `plugin.json` / `mcp.json` / `skills/` 格式；远程 server 只含 `type` 和 `url`，原生宿主通过标准元数据发现 OAuth 并完成 DCR/PKCE。不含企业 ID 或凭据；真实企业、身份与授权范围在第一方流程中绑定。插件本身不授予业务权限，实际能力以目标服务返回的工具、当前账号权限和本次 OAuth 范围为准。

## 员工业务、图片与文件

员工连接后先核对 `get_identity`，再发现当前获权的业务能力；平台生图通过独立的 `get_media_capabilities` 查询，不能把业务目录当作全部平台能力。用户指定灼见生图时，调用实际可用的 `generate_image`，由 SaaS 使用与网页相同的模型权限、额度和工作空间创建规则执行，不改用宿主订阅生图。

本人一次 OAuth 授予 `files:write` 后，可按明确生图意图创建新文件，无需逐图业务确认；业务修改及外部文件上传仍遵守原有第一方确认流程，宿主工具允许不能代替。图片提交返回持久任务 `jobId`，通过 `get_media_job` 查询同一任务；排队、执行中、失败、未知与正式交付分开呈现，未知结果不更换 `requestId` 重发。完成以正式 file/version/hash 等回执为准。没有实际视频工具时不承诺生视频。

## 企业管理员后台管理

企业管理员使用本人身份明确授予 `admin:manage:read/write`，通过 `discover_admin_capabilities` 发现管理目录，使用 `query_admin` 查询、`execute_admin` 提交本人确认后的修改。现有显式目录覆盖 164 项管理操作，注册服务器和代码上传除外；不开放平台专属、退役功能或员工/机器身份接口。服务尚未部署或工具未实际出现时，不宣称管理能力已上线。

四步连接默认只读；管理写权限须由本人明确选择，旧授权不自动扩权。密码和长期密钥只在本人第一方页面输入，不交给 AI。文件操作另外受文件范围及连接所选工作空间约束，未选和后续新增空间不会自动开放。完整步骤见[业务、图片与文件说明](skills/zhuojian-enterprise/SKILL.md)。

## 首次使用与更新

安装获准且核验通过的第一方发行包后，运行插件设置引导，或直接说“检查灼见企业连接并引导我登录”。先检查实际工具；缺少工具时，用随包只读脚本区分网络问题、OAuth 发现异常、宿主连接状态和需要本人授权，不把“已安装”或 `not_logged_in` 当作完整诊断。网络可达且用户要求连接时，宿主发起原生登录，由本人核对企业、身份和范围；浏览器已有灼见登录不等于插件已授权。

授权后刷新实际工具并核对身份和获权目录；没有终端环境的宿主使用原生连接界面，明确自动诊断限制，不要求员工安装开发工具。详见[首次接入引导](skills/setup/SKILL.md)。

Codex marketplace 交付须完整解压 marketplace ZIP，将含 `.agents/plugins/marketplace.json` 的根目录作为来源；不要把单独插件目录或 ZIP 文件当作 marketplace 根目录。索引保留可选安装和安装时认证策略，实际 OAuth 触发时机以宿主为准。构建和验证不会登记来源或安装插件。

使用灼见同域的国内发行入口，不要求员工操作 Git 或访问 GitHub。固定本地 ZIP 来源需要一次迁移；支持更新的 Codex 由宿主原生机制检查已登记来源。来源核验优先读取原生 `installed` 条目，未安装时再读取可安装目录；失败保留现有安装。未核对最终来源、实际版本及当前聊天加载状态时，不报告已完成更新。

真实业务写入、图片交付、管理员管理和各宿主授权分别验收；不能由一个客户端或历史回执推定所有宿主均已通过。官方格式：[OpenAI 插件打包](https://developers.openai.com/plugins/build/plugins)。Skill 为业务说明规范源，WorkBuddy 的共享副本由构建工具同步。
