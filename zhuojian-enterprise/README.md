# 灼见企业 · Codex 连接包

源码目录是连接模板，其中 `.invalid` 地址不能使用；维护者通过构建脚本明确传入 MCP 地址，生成可安装的独立试点包。实际发布与宿主验收状态以项目交接回执为准。

包采用根目录 `plugin.json` / `mcp.json` / `skills/` 格式；远程 server 只含 `type` 和 `url`，原生宿主通过标准元数据发现 OAuth 并完成 DCR/PKCE。不含企业 ID 或凭据；真实企业、身份与授权范围在第一方流程中绑定。插件本身不授予业务权限。业务操作和上传须由本人在第一方页面确认，宿主工具允许不能代替。

本插件可通过构建工具同时生成的 Codex marketplace 交付：完整解压 marketplace ZIP 后，将含 `.agents/plugins/marketplace.json` 的根目录作为 marketplace 来源。不要把此单独插件目录或 ZIP 文件当作 marketplace 根目录。索引声明可选安装及安装时认证策略；实际 OAuth 可能在宿主连接时发起，以宿主为准。构建和验证不会登记来源或安装插件。

## 首次使用

安装后运行插件的设置引导，或直接说“检查灼见企业连接并引导我登录”。`0.1.2` 的引导先检查本轮实际工具；缺少工具时，用随包只读脚本区分网络问题、OAuth 发现异常、宿主连接状态和需要本人授权，不把“已安装”或 `not_logged_in` 当作完整诊断。

网络可达且需要授权时，宿主发起原生登录，由本人在灼见第一方页面核对企业、身份和范围。浏览器已有灼见登录不等于插件已授权。网络认证、证书错误或服务故障时，引导提供实测原因和对应下一步；换热点只可用于排查，不是员工正常使用的条件。

授权后检查实际工具，必要时刷新连接或在新聊天继续；只有 `get_identity` 和获权目录返回成功，才报告企业连接验证完成。没有终端/代码环境的宿主使用原生连接界面，并明确自动诊断的未测范围。详见[首次接入引导](skills/setup/SKILL.md)。

构建不代表服务可用或所有客户端流程已验收。`0.1.2` 的修改、安装及实际验收以对应交接为准；2026-10-12 的 `0.1.1` Alphabet 试点只证明其当时真实 OAuth 和三项读取工具验收，不能代替新版本验证。真实业务写入、上传、企业管理员宿主和 WorkBuddy 的完整流程仍须独立验收。

官方格式：[OpenAI 插件打包](https://developers.openai.com/plugins/build/plugins)。包内 Skill 是业务说明的唯一编辑源；WorkBuddy 副本由仓库构建工具同步。

## 更新

员工使用灼见同域的国内发行入口；不需要访问 GitHub、配置 VPN 或操作 Git。首次接入引导会检查国内入口是否就绪，并在用户要求安装升级或自动更新后通过宿主原生机制配置。固定本地 ZIP 来源需要一次迁移，不能声称源码升级就能自动更新已经安装的静态旧包。

支持的 Codex 会在宿主启动时后台检查已登记的 Git marketplace，并更新安装缓存。失败时保留现有安装；本聊天是否加载新版仍须核验，必要时新开聊天。未完成来源及实际版本检查时，不报告自动更新已启用。维护者的 GitHub 仓库不是员工更新的必要入口。
