# 灼见企业 · Codex 连接包

源码目录是连接模板，其中 `.invalid` 地址不能使用；维护者通过构建脚本明确传入 MCP 地址，生成可安装的独立试点包。实际发布与宿主验收状态以项目交接回执为准。

包采用根目录 `plugin.json` / `mcp.json` / `skills/` 格式；远程 server 只含 `type` 和 `url`，原生宿主通过标准元数据发现 OAuth 并完成 DCR/PKCE。不含企业 ID 或凭据；真实企业、身份与授权范围在第一方流程中绑定。插件本身不授予业务权限。业务写操作和外部文件上传须由本人在第一方页面确认，宿主工具允许不能代替。

本目录为 **`0.1.4` 生图候选**，元数据包含“使用灼见生成图片”示例，尚未发行。不会覆盖已发布 `0.1.3` 或改动本机安装缓存；实际可用工具与生图验收仍以当前服务和真实回执为准。

## 灼见图片服务

连接后分别查询子系统业务目录与 `get_media_capabilities`，不能把业务目录当作全部平台能力。用户指定灼见生图时，调用当前公开的 `generate_image`，由 SaaS 使用与网页相同的模型权限、额度和工作空间创建规则执行；不改用宿主订阅生图。本人一次 OAuth 授予 `files:write` 后，可按明确生图意图创建新文件，无需逐图业务确认；业务修改及外部文件上传仍遵守原确认流程。

图片提交返回持久任务 `jobId`，通过 `get_media_job` 读取原任务。排队、执行中、失败、未知与正式交付分开呈现；未知结果不更换 `requestId` 重发。只有正式 file/version/hash 等回执才能证明完成。本轮仅接图片，没有当前视频工具时不承诺生视频。完整步骤见[业务、图片与文件说明](skills/zhuojian-enterprise/SKILL.md)。

本插件可通过构建工具同时生成的 Codex marketplace 交付：完整解压 marketplace ZIP 后，将含 `.agents/plugins/marketplace.json` 的根目录作为 marketplace 来源。不要把此单独插件目录或 ZIP 文件当作 marketplace 根目录。索引声明可选安装及安装时认证策略；实际 OAuth 可能在宿主连接时发起，以宿主为准。构建和验证不会登记来源或安装插件。

## 首次使用

候选正式发行并获准安装后，运行插件的设置引导，或直接说“检查灼见企业连接并引导我登录”。引导沿用 `0.1.3` 的连接检查，先检查本轮实际工具；缺少工具时，用随包只读脚本区分网络问题、OAuth 发现异常、宿主连接状态和需要本人授权，不把“已安装”或 `not_logged_in` 当作完整诊断。

网络可达且需要授权时，宿主发起原生登录，由本人在灼见第一方页面核对企业、身份和范围。浏览器已有灼见登录不等于插件已授权。网络认证、证书错误或服务故障时，引导提供实测原因和对应下一步；换热点只可用于排查，不是员工正常使用的条件。

授权后检查实际工具，必要时刷新连接或在新聊天继续；只有 `get_identity` 和获权目录返回成功，才报告企业连接验证完成。没有终端/代码环境的宿主使用原生连接界面，并明确自动诊断的未测范围。详见[首次接入引导](skills/setup/SKILL.md)。

构建不代表服务可用或所有客户端流程已验收。`0.1.4` 生图候选须单独核验授权、任务、预览和正式文件回执；已发布 `0.1.3` 的历史验收不能代替本候选验证。真实业务写入、上传、企业管理员宿主和 WorkBuddy 的完整流程仍须独立验收。

官方格式：[OpenAI 插件打包](https://developers.openai.com/plugins/build/plugins)。包内 Skill 是业务说明的唯一编辑源；WorkBuddy 副本由仓库构建工具同步。

## 更新
